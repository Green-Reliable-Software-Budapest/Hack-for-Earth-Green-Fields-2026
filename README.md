# Hack for Earth 2026 — Greener Fields

**Green + Open Software · October 2026**

This repository is the companion technical workspace for **HACK4EARTH 2.0 — Greener Fields**, a month-long challenge exploring how open technology can make the systems we depend on more **secure, efficient and resilient**.

> The competition itself lives on Kaggle. This repository contains technical guidance, open resources and reference examples.
>
> **[Join the hackathon on Kaggle →](https://www.kaggle.com/competitions/hack-4-earth-2-0-greener-fields)**

## Three directions

### SECURE

Build technologies that make digital systems more trustworthy and defensible.

Cybersecurity · Privacy · Cryptography · Software supply chains · Dependency security · Trustworthy systems

### EFFICIENT

Build technologies that achieve useful outcomes while using computing, energy and infrastructure resources more deliberately.

Green software · Cloud · Compute · Data · AI · Hardware · Measurement · Observability

### RESILIENT

Build technologies that help essential systems continue, adapt or recover under pressure.

Food · Water · Energy · Communications · Climate · Environmental systems · Critical infrastructure

Projects may cross several areas, but each team selects one primary track for judging.

## The goal

Identify a real problem, build an open technical solution, and provide evidence that it works.

There is no mandatory dataset and no requirement to use AI.

What matters is whether you can explain:

- What problem are you solving?
- What did you build?
- Does it work?
- What evidence supports your claims?
- Can somebody else inspect, reproduce or extend it?

## October rhythm

| Period | Question | Focus |
| --- | --- | --- |
| 1–7 October | Who Builds the Commons? | Open source, maintainership, trust, software supply chains |
| 8–14 October | Who Pays for the Commons? | Infrastructure costs, sustainable open-source models |
| 15–21 October | Can You Measure What You Built? | Evidence, efficiency, measurement |
| 22–28 October | Does It Survive Pressure? | Reliability, failure, resilience |
| 29–31 October | Final Sprint | Documentation, evidence and submission |

Final submissions close on **31 October 2026**. The definitive deadline is the one displayed on Kaggle.

## Repository purpose

This repository is intentionally small.

It is **not** a second competition platform and it is not where teams submit entries. Kaggle remains the canonical location for competition rules, tracks, Writeups and judging.

Use this repository for:

- technical guidance
- examples
- shared learning resources
- corrections and improvements to programme materials

Do not submit competition entries as pull requests to this repository.
